\section*{Abstract}

London Fire Brigade publishes detailed incident and mobilisation records, but borough demand, incident type, response-time denominators, appliance-level mobilisation, and spatial uncertainty all affect how response performance should be interpreted. This project asks how an uncertainty-aware visual analytics dashboard can support structured inspection of London Fire Brigade incident demand and first-pump response performance using public open data.

The project builds a reproducible Python data pipeline over the 2024--2026 LFB Incident Records, LFB Mobilisation Records, London borough boundaries, and a public fire-station address/postcode table. The processed outputs feed a Flask API and a D3.js dashboard with linked borough map, monthly trend, response-time distribution, and ranking-table panels. Only 37.9\% of incident rows have precise coordinates, so point-level analysis is kept separate from borough summaries. Mobilisation results use matched canonical incidents, while station context distinguishes incident-derived assignment footprints from postcode-geocoded historical addresses.

The dashboard shows borough-level response-performance disparities together with their denominators and data limitations. Among 278,468 incidents with a recorded first-pump time, the author's share above 360 seconds is 32.4\% (95\% Wilson CI 32.3--32.6\%); this is not LFB's official per-incident failure rate. The highest borough values are Hillingdon (52.2\%), Bromley (47.6\%), and Richmond upon Thames (45.2\%). The ranking remains stable when false alarms are excluded. The interface shows recorded denominators, confidence intervals, small-sample warnings, and the partial final month. Mobilisation results and historical station addresses add separate context. A small formative evaluation found that the linked views helped participants compare boroughs, although some original tasks asked for functions the interface did not provide and the submitted workspace contains no raw per-session notes.
